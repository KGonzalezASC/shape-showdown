# Open-source Tetris bot options for Shape Showdown

Reviewed 2026-08-05. Sources below are the projects' own GitHub repositories and source files; no secondary descriptions were used.

## Short recommendation

Use **Cold Clear** as the first external benchmark or helper-bot candidate. Its public C API already accepts a 10×40 occupancy field, hold/B2B/combo state, and an explicit incoming-garbage forecast. Use **Nana** as the best research reference for versus evaluation and cancellation strategy. If a native dependency is undesirable, port the smaller **TetrisLive** planner as a deliberately modest baseline. **Zetris/MisaMino** is a strong attack-aware reference, but its reusable core is coupled to a DLL and game-memory adapters rather than exposed as a clean engine library.

Shape Showdown's natural adapter boundary is a placement planner: snapshot `board`, `activePiece`, `holdPiece`, `nextQueue`, and `pendingGarbage`; ask the bot for a target placement; translate that placement into `rotate*`, movement, `hardDrop`, and `hold` actions. Keep line-clear scoring, attack calculation, packet timing, poison/custom cells, and top-out authoritative in [`stepPlayer`](../../server/tetris/engine.ts) and [`GameManager`](../../server/GameManager.ts). The local model is a 10×20 simulation board with an 18-row visible arena, `G` garbage cells, and delayed `PendingGarbagePacket`s ([`types.ts`](../../src/types.ts), [`constants.ts`](../../src/constants.ts)).

## Comparison

| Candidate | Language/runtime and license | Explicit versus / garbage behavior | Shape Showdown fit |
|---|---|---|---|
| [Cold Clear](https://github.com/MinusKelvin/cold-clear) | Rust; MPL-2.0. The repository describes it as a modern Tetris Versus bot and exposes both a Rust library and C API ([README](https://github.com/MinusKelvin/cold-clear/blob/master/README.md), [license](https://github.com/MinusKelvin/cold-clear/blob/master/LICENSE)). | The C API starts from an existing board/hold/B2B/combo state, requests a move with an `incoming` garbage-line forecast, and says to reset the simulated field when garbage is received. Its weights include attack-oriented terms such as combo garbage, B2B clears, T-spins, perfect clears, and `CC_PC_ATTACK` ([C API](https://github.com/MinusKelvin/cold-clear/blob/master/c-api/coldclear.h#L2-L14)). | **Best direct fit.** Shape Showdown's 10×20 occupancy can be embedded in Cold Clear's 10×40 field with an explicit row-origin/padding adapter, and the API already separates decision-making from host-side movement. Costs: native Rust/C integration, MPL obligations for distributed modifications, and loss of Shape Showdown-specific poison/Wildcard semantics unless those are projected into occupancy or handled by a wrapper policy. The repo is archived, so treat it as a stable snapshot rather than an actively maintained dependency ([repository status](https://github.com/MinusKelvin/cold-clear)). |
| [Nana](https://github.com/nightcrab/nana) | C++; MIT ([README](https://github.com/nightcrab/nana/blob/master/README.md), [license](https://github.com/nightcrab/nana/blob/master/LICENSE)). CMake build; also emits a JSON-based Tetris Bot Protocol executable. | It is explicitly a two-player/Versus search program. `EmulationGame` tracks buffered garbage and a garbage meter, applies attack cancellation, sends residual damage to an opponent model, and applies incoming garbage in capped batches. `Opponent` models attack tactics, incoming garbage layers, cancellation pressure, and attack/death outcomes ([EmulationGame](https://github.com/nightcrab/nana/blob/master/cpp/Tetris/game/EmulationGame.cpp#L51-L121), [Opponent](https://github.com/nightcrab/nana/blob/master/cpp/Tetris/game/Opponent.hpp#L219-L257), [garbage processing](https://github.com/nightcrab/nana/blob/master/cpp/Tetris/game/Opponent.hpp#L532-L615)). | **Best versus-logic reference; medium porting cost.** It has the right conceptual state variables for Shape Showdown, but its opponent is deliberately simplified and its search is built around its own C++/bitboard engine. Port the attack-aware evaluation/cancellation ideas or run it behind a protocol adapter; do not assume its board transitions match Shape Showdown's SRS, delayed packets, poison, or shop effects. |
| [Zetris + MisaMinoNET](https://github.com/ZetrisAI/Zetris) | Zetris host/adapters are C# and BSD-3-Clause ([README](https://github.com/ZetrisAI/Zetris/blob/master/README.md), [license](https://github.com/ZetrisAI/Zetris/blob/master/LICENSE)). The reusable MisaMino wrapper is C++/.NET and its repository's license file only says “Copyleft by Misakamm,” so its redistribution terms need clarification ([MisaMinoNET README](https://github.com/ZetrisAI/MisaMinoNET/blob/master/README.md), [license file](https://github.com/ZetrisAI/MisaMinoNET/blob/master/LICENSE)). | Zetris is a MisaMino-based bot for Puyo Puyo Tetris/TETR.IO and documents local multiplayer-versus play. The PPT adapter reads the game's pending garbage, calculates garbage from the current attack state, feeds `garbage_left` into the MisaMino search, and includes a garbage-blocking decision ([Zetris README](https://github.com/ZetrisAI/Zetris/blob/master/README.md#local-installation-with-puyo-puyo-tetris), [PPTBot garbage/input path](https://github.com/ZetrisAI/Zetris/blob/master/Zetris.PPT/PPTBot.cs#L84-L116), [prediction path](https://github.com/ZetrisAI/Zetris/blob/master/Zetris.PPT/PPTBot.cs#L157-L166)). | **Strong behavior reference, weak drop-in candidate.** Its attack/survival seam is unusually relevant, but the host depends on memory scanning, virtual gamepad input, and a separately imported MisaMino DLL. Reusing the algorithm means extracting/porting the actual search and explicitly resolving the MisaMinoNET license; reusing the PPT integration would be the wrong architectural seam for a server-authoritative TypeScript engine. |
| [TetrisLive](https://github.com/wyndwarrior/TetrisLive) | Java/OpenGL; GPL-3.0 ([README/license](https://github.com/wyndwarrior/TetrisLive/blob/master/README.md)). | The game supports multiplayer battles and its robot is a depth-first, multi-piece search with height/canyon/shape and line-clear heuristics ([README](https://github.com/wyndwarrior/TetrisLive/blob/master/README.md#features), [TSRobot](https://github.com/wyndwarrior/TetrisLive/blob/master/src/TSRobot.java#L8-L17)). The game itself stores incoming garbage, cancels it with cleared lines, processes it into rows, and sends/receives attack counts over multiplayer messages ([TSTetris](https://github.com/wyndwarrior/TetrisLive/blob/master/src/TSTetris.java#L43-L68), [garbage application](https://github.com/wyndwarrior/TetrisLive/blob/master/src/TSTetris.java#L352-L396), [multiplayer path](https://github.com/wyndwarrior/TetrisLive/blob/master/src/TSRenderMP.java#L106-L121)). | **Good lightweight baseline.** The planner's board/hold/preview model is easy to port to TypeScript, and the post-garbage board is fed back into the robot. However, the heuristic does not score incoming garbage or attack tradeoffs directly; it is a line-clear/stack-shape bot inside a versus-capable game, not a modern garbage-aware competitive bot. GPL-3.0 also matters if code is copied into a distributed combined work. |

## No-go control

[nuno-faria/tetris-ai](https://github.com/nuno-faria/tetris-ai) is a useful single-player RL example, but not a candidate for this task. Its documented state features are lines, holes, bumpiness, heights, and pieces; its reward is score/line clearing, with no opponent, attack, incoming-garbage, or garbage-row state ([README](https://github.com/nuno-faria/tetris-ai/blob/master/README.md#game-state), [MIT license](https://github.com/nuno-faria/tetris-ai/blob/master/LICENSE)). Adapting it to versus play would require changing the environment, state representation, reward, training data, and action timing—not merely adding a Shape Showdown adapter.

## Practical selection order

1. **Cold Clear:** benchmark placement quality and survival against recorded Shape Showdown snapshots through a process/native boundary; keep Shape Showdown authoritative for all effects and attacks.
2. **Nana:** borrow versus evaluation ideas if the goal is attack-aware strategy or a deliberately abstract training opponent.
3. **TetrisLive:** port only if a small, dependency-free baseline is more valuable than competitive strength.
4. **Zetris/MisaMino:** consult for advanced attack-aware heuristics, subject to the MisaMino license and a full engine port.

No production code was changed for this research.
